# Многофункциональный Высоконагруженный Веб-Сервер на сокетах

Учебный высокопроизводительный веб-сервер прикладного уровня, написанный с нуля на Python с использованием низкоуровневой библиотеки `socket`. Реализует многопоточную обработку запросов, виртуальный хостинг, двухуровневое кэширование, обратный прокси и систему обеспечения качества обслуживания (QoS).

**Авторы:**
- **Роман** - сетевой слой, двухуровневое кэширование, управление трафиком и таймаутами.
- **Данил** - парсер HTTP, подсистема сборки ответов, логика Reverse Proxy.

---

## Ключевые возможности

### Сетевой контроль и QoS
- **Защита от зависших соединений:** раздельные таймауты `read_timeout` (защита от Slowloris) и `write_timeout` (освобождение ресурсов при медленном клиенте).
- **Двустороннее ограничение скорости:** класс `RateLimiter` на основе `time.monotonic()` жёстко лимитирует пропускную способность — `upload_limit_bps` и `download_limit_bps`.

### Продвинутый FileManager и двухуровневое кэширование
- **In-Memory Cache (файлы < 50 МБ):** мелкие статические файлы целиком выгружаются в RAM для мгновенной отдачи без обращения к диску.
- **FD-Cache и потоковое чтение (файлы > 50 МБ):** для тяжёлых файлов кэшируются только файловые дескрипторы (`OrderedDict` с вытеснением). Данные считываются порциями через `os.pread` со смещением — без гонок при многопоточном доступе.
- **Инвалидация кэша:** атомарный `os.stat()` при каждом запросе проверяет `st_mtime`; при изменении файла кэш сбрасывается автоматически.
- **Autoindex:** если `index.html` в директории отсутствует, сервер генерирует HTML-листинг файлов на лету.

### Виртуальный хостинг
На одном IP и порту сервер изолированно обслуживает несколько доменов (например, `localhost` и `site2.com`). Маршрутизация по заголовку `Host` с поиском O(1) через хеш-таблицу конфигурации. Встроена защита от Path Traversal (`../`).

### Потоковый Reverse Proxy
Запросы на префикс `/api` перенаправляются на upstream-сервер. Проксирование реализовано через генераторы Python (`yield`) — при медленном клиенте итерация приостанавливается, что автоматически замедляет чтение из upstream-сокета и предотвращает переполнение RAM (backpressure).

## Архитектура проекта

```
WebServer/
├── server/
│   ├── core/
│   │   ├── config.py           # Загрузка и валидация конфигурации JSON
│   │   ├── handler.py          # Логика обработки HTTP-методов и проксирования
│   │   └── server.py           # Сетевой слой: сокеты, треды, таймауты, лимитеры
│   ├── protocol/
│   │   ├── parser.py           # Низкоуровневый парсинг сырых байт HTTP-запроса
│   │   └── response_builder.py # Конструктор HTTP-ответов и заголовков
│   └── utils/
│       ├── file_manager.py     # Кэширование статики и файловые дескрипторы
│       ├── logger.py           # Потокобезопасное логирование событий
│       └── rate_limiter.py     # Контроллер ограничения скорости
├── site2/                      # Директория виртуального хоста site2.com
├── static/                     # Директория хоста по умолчанию (localhost)
├── Tests/                      # Модульные и интеграционные тесты
├── main.py                     # Точка входа
└── webserver.log               # Системный лог
```

## Конфигурация (config.json)

```json
{
  "host_ip": "0.0.0.0",
  "port": 8080,
  "root_dir": "./static",
  "log_file": "webserver.log",

  "ssl_cert": "./localhost+1.pem",
  "ssl_key": "./localhost+1-key.pem",

  "read_timeout": 5,
  "write_timeout": 5,
  "upload_limit_bps": 1048576,
  "download_limit_bps": 1048576,

  "servers": {
    "localhost": "./static",
    "site2.com": "./site2"
  }
}
```

- `read_timeout` / `write_timeout` - лимиты ожидания сети (в секундах).
- `upload_limit_bps` / `download_limit_bps` - ограничения скорости (байт/с). Значение `0` отключает лимит.

## Примеры тестирования

Виртуальный хост `localhost`:

```bash
curl -H "Host: localhost" http://localhost:8080/index.html
```

Виртуальный хост `site2.com` (тот же порт):

```bash
curl -H "Host: site2.com" http://localhost:8080/index.html
```

Reverse Proxy:

```bash
curl http://localhost:8080/api/get
```

Обработка ошибок (404) с выводом заголовков:

```bash
curl -i http://localhost:8080/prizrak.html
```

Проверка защиты от Path Traversal:

```bash
curl --path-as-is http://localhost:8080/../../etc/passwd
```
